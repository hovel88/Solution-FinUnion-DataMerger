# entities.md — ключевые бизнес-сущности: FinUnion + RetailBank

> Назначение документа: определить ключевые бизнес-сущности для объединенной компании FinUnion Group после слияния с RetailBank.

## Реестр сущностей

Сущности выделялись по трём критериям:

1. **Есть жизненный цикл**: объект создают, меняют, закрывают
2. **Участвует в нескольких сценариях**: используется разными отделами
3. **Есть бизнес-владелец**: есть ответственный за корректность

!!! . Надо отметить, что изначально, пользуясь этими критериями, я сформировал немного другой набор сущностей, а некоторые сущности даже не выделил. Но затем, чуть больше прочитал про BIAN, как референсную модель для банковской специфики, поделил сущности иначе и всё переделал.
!!! . Например, сначала я Клиента разбивал на ФЛ, ЮЛ, т.к. у них разные владельцы, разные сценарии, разные жизненные циклы. И мне не нравилось, как по итогу все приводить к единым идентификаторам. Потом я выяснил, что в BIAN есть Party на этот случай, у него есть свой владелец и он в себя включает все эти разделения путем внутренних аттрибутов. Что лучше ложится на идею единого идентификатора.
> 
Большая часть сущностей взята из контекста, целей, ограничений самой задачи. И дополнена некоторыми из BIAN Service Landscape.

### 1. Клиент (Party)

| Критерий | Описание |
| -- | -- |
| **Описание** | Обобщающая сущность для всех субъектов права: физических лиц, юридических лиц, ИП. Представляет сторону в банковских отношениях |
| **Атрибуты** | party_id (корпоративный ID)<br>party_type (ФЛ/ЮЛ/ИП)<br>ИНН<br>ФИО/Наименование<br>Паспортные данные (для ФЛ)<br>ОГРН (для ЮЛ)<br>Телефон<br>Адрес<br>email |
| **Связи** | 1:N с Договором<br>1:N со Счетом<br>1:N с Картой<br>1:N с Кредитом<br>1:N с Обращением<br>1:N с Согласием<br>1:N с Документом |
| **Системы-источники** | FU CRM, RB CRM, FU Core, RB Core |
| **Критерий включения** | Центральный объект клиентского профиля, участвует во всех сценариях. Есть владелец (Data Office / розничный блок) |
| **Проблемы качества** | Дубли клиентов в FU и RB (разные ID), разные форматы ФИО, неполные паспортные данные, устаревшие адреса |

### 2. Счет (Account)

| Критерий | Описание |
| -- | -- |
| **Описание** | Банковский счет клиента: текущий, сберегательный, расчетный. Отражает движение денежных средств |
| **Атрибуты** | account_id<br>party_id<br>account_type<br>номер счета<br>валюта<br>баланс<br>статус (открыт/закрыт/заблокирован)<br>дата открытия<br>branch_id |
| **Связи** | N:1 с Клиентом<br>1:N с Транзакцией<br>1:N с Картой<br>N:1 с Офисом |
| **Системы-источники** | FU Core, RB Core |
| **Критерий включения** | Операционная сущность с жизненным циклом, разные модели в FU и RB, критична для отчетности |
| **Проблемы качества** | Разные модели счетов в FU Core и RB Core, несовпадающие статусы, разные валюты |

### 3. Карта (Card)

| Критерий | Описание |
| -- | -- |
| **Описание** | Платежная карта, выпущенная к счету клиента |
| **Атрибуты** | card_id<br>account_id<br>party_id<br>номер карты (маскированный)<br>тип (дебетовая/кредитная)<br>платежная система<br>срок действия<br>статус |

| **Критерий включения** | Операционная сущность, разные статусы и тарифы в FU/RB |
| **Проблемы качества** | Разные статусы карт, несинхронизированные тарифы |

| Критерий | Описание |
| -- | -- |
| **Описание** | Именно как юридическая сущность, договор между клиентом и банком: договор счета, кредитный договор, договор карты |

| **Критерий включения** | Юридический факт, связывает клиента и продукт, участвует в отчетности |
| **Проблемы качества** | Разные модели договоров, несинхронизированные сроки |

### 6. Транзакция (Transaction)

| Критерий | Описание |
| -- | -- |
| **Описание** | Финансовая операция по счету: списание, зачисление, перевод |
| **Атрибуты** | transaction_id<br>account_id<br>сумма<br>валюта<br>тип<br>таймштамп<br>статус<br>назначение |
| **Связи** | N:1 со Счетом<br>N:1 с Картой (хотя вероятно карта привязана к счету, поэтому связь будет через Счет) |
| **Системы-источники** | FU Core, RB Core, FU Cards, RB Cards |
| **Критерий включения** | Событийная сущность, высокая частота появления, основа для отчетности и аудита |
| **Проблемы качества** | Разные форматы, дубли при повторной обработке |

### 7. Платеж (Payment)

| Критерий | Описание |
| -- | -- |
| **Описание** | Платежное поручение: перевод между счетами, оплата услуг, погашение кредита |
| **Атрибуты** | payment_id<br>from_account_id<br>to_account_id<br>сумма, валюта<br>тип<br>статус<br>дата |

| **Проблемы качества** | Разные статусы и форматы, несинхронизированные справочники |
