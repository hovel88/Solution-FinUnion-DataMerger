# storage-strategy.md — стратегия хранения данных: FinUnion + RetailBank

> Назначение документа: определить типы хранилищ для разных групп данных объединённой компании FinUnion Group. Это нужно, чтобы принять решение где хранить операционные данные, аналитику, документы, исторические и событийные данные.

## Разделение контуров

Данные объединенной FinUnion + RetailBank можно разделить на несколько контуров:

- **Операционный контур** (OLTP) — счета, договоры, платежи, транзакции
- **Аналитический контур** (OLAP) — DWH, Lakehouse, BI
- **Мастер-данные** (MDM) — клиенты, справочники
- **Документы** (Object Storage) — сканы, архивы
- **Специализированный контур** — Поисковый движок, Графовая БД

## Матрица совместимости: категория данных × тип хранилища

| Категория данных | OLTP БД | MDM | DWH | Data Lakehouse | Object Storage | Графовая БД | Поисковый движок |
| -- | -- | -- | -- | -- | -- | -- | -- |
| Публичные | Да | Да | Да | Да | Да | Да | Да |
| Внутренние | Да | Да | Да | Да | Да | Да | Да |
| Конфиденциальные | Да | Да | Можно **(маскирование)** | Можно **(маскирование)** | Можно **(шифрование)** | Можно **(токенизация)** | Можно **(маскирование)** |
| Регулируемые (ПДн) | Можно **(шифрование, RBAC, аудит)** | Да **(шифрование, RBAC)** | Можно **(токенизация/маскирование)** | Можно **(токенизация)** | Можно **(шифрование)** | Можно **(токенизация)** | Можно **(маскирование)** |
| Регулируемые (банковская тайна) | Можно **(шифрование, RBAC, аудит)** | Можно **(шифрование, RBAC)** | Можно **(маскирование)** | Можно **(токенизация)** | Можно **(шифрование)** | Можно **(токенизация)** | Можно **(маскирование)** |
| Критичные секреты | Нельзя! | Нельзя! | Нельзя! | Нельзя! | Нельзя! | Нельзя! | Нельзя! |

**OLTP БД** — создан для ACID и транзакций. ПДн можно, но только с шифрованием и RBAC (стандарт для банков).
**MDM** — создан для мастер-данных. ПДн это основной сценарий, поэтому Да, при условии шифрования.
**DWH** — аналитика, регламентированная отчётность. ПДн только токенизированные/маскированные (нельзя "сырые" ПДн).
**Lakehouse** — большие данные, исторические и событийные данные. ПДн только токенизированные (большой риск утечки из файлов).
**Object Storage** — файлы, документы и архивы. ПДн (например, паспорт) можно, но с шифрованием (SSE-S3).
**Графовая БД** — связи. ПДн только токенизированные узлы (иначе утекший граф представляет соцсеть).
**Поисковый движок** — полнотекстовый поиск. ПДн можно только маскированные (риск утечки из индекса).
**Критичные секреты** — пароли, токены, ключи. Не хранятся ни в одном из этих хранилищ. Для них нужен отдельный Vault-контур с ротацией.

## Логика выбора хранилищ

Оценивать будем по режиму доступа к данным (ограничение), профилю нагрузки (оптимизация), форме и характеру запросов.

У каждой сущности есть своё одно основное хранилище. Однако часто сущность должна перетекать и в дополнительное хранилище, в виде исторических данных, агрегаций и т.д., поэтому укажем и дополнительные типы хранилищ.

| ## | Сущность | Категория данных | Режим доступа отсекает | Профиль нагрузки | Итоговое хранилище | Дополнительное хранилище | Необходимые меры |
| -- | -- | -- | -- | -- | -- | -- | -- |
| 01 | Клиент (Party) | Регулируемые (ПДн) | Любые хранилища без шифрования | Мастер-данные (единый ID), справочная | MDM | OLTP (реплика), DWH (агрегация) | Шифрование, RBAC, аудит, маскирование, дедупликация |
| 02 | Договор (Contract) | Регулируемые (банковская тайна) | DWH (без маскирования), Lakehouse (без токенизации) | OLTP (ACID, транзакции), операционная | OLTP | DWH | Шифрование, RBAC, аудит, маскирование |
| 03 | Счёт (Account) | Регулируемые (банковская тайна) | Object Storage (не для транзакций) | OLTP (ACID, точечные запросы), операционная | OLTP | DWH | Шифрование, маскирование, RBAC |
| 04 | Карта (Card) | Регулируемые (банковская тайна) | Lakehouse (без токенизации), DWH (без маскирования) | OLTP (ACID, статусы), операционная | OLTP | DWH | Токенизация, маскирование, шифрование |
| 05 | Кредит (Loan) | Регулируемые (банковская тайна) | DWH (без маскирования) | OLTP (ACID, графики), операционная | OLTP | DWH | Шифрование, RBAC, аудит, маскирование |
| 06 | Транзакция (Transaction) | Регулируемые (банковская тайна) | Object Storage (не для транзакций) | OLTP (высокая частота), операционная + Lakehouse (аггрегации), историческая | OLTP | Lakehouse | Шифрование, RBAC, аудит, агрегация для аналитики |
| 07 | Платёж (Payment) | Регулируемые (банковская тайна) | DWH (без маскирования) | OLTP (ACID), операционная | OLTP | DWH | Шифрование, RBAC, аудит, маскирование |
| 08 | Продукт (Product) | Внутренние (банковская тайна) / Публичные | Публичное облако (без RBAC) | Мастер-данные (единый ID), справочная | MDM | DWH | RBAC, аудит, маскирование тарифов для внешних |
| 09 | Обращение (Request) | Регулируемые (ПДн в тексте) | Object Storage (не для поиска) | OLTP (транзакции), операционная + SearchEngine, поисковая | OLTP | SearchEngine | Шифрование, RBAC, маскирование |
| 10 | Справочник (Reference) | Внутренние / Публичные | Публичное облако (без RBAC для внутренних) | Мастер-данные (единый ID), справочная | MDM | DWH | RBAC для внутренних, публичный доступ для открытых |
| 11 | Согласие (Consent) | Регулируемые (152-ФЗ) | DWH (без аудита), Lakehouse (без токенизации) | OLTP (ACID, жизненный цикл) | OLTP | — | Шифрование, RBAC, аудит, журнал выдачи/отзыва |
| 12 | Скоринг (Risk Score) | Конфиденциальные (банковская тайна) | Object Storage (не для вычислений) | OLTP (расчёт), операционная + Lakehouse (ML), агригирующая | OLTP | Lakehouse | Шифрование, RBAC, аудит, маскирование баллов |
| 13 | Документ (Document) | Регулируемые (ПДн, паспорт) | OLTP (тяжёлые файлы), DWH (не для файлов) | Файлы, версионирование, индексирование | Object Storage | SearchEngine | Шифрование (SSE-S3), RBAC, аудит, маскирование, токенизация |
| 14 | Офис (Branch) | Публичные (адреса) / Внутренние (коды) | Публичное облако (без RBAC для кодов) | Мастер-данные (единый ID), справочная | MDM | DWH | Публичный доступ для адресов, RBAC для внутренних кодов |
| 15 | Тариф (Tariff) | Внутренние (банковская тайна) | Публичное облако (без RBAC) | Мастер-данные (единый ID), справочная | MDM | DWH | RBAC, аудит, маскирование для внешних |

## Детализация по типам хранилищ

### 1. OLTP БД (операционные данные)

| Параметр | Описание |
| -- | -- |
| Структура | Реляционная СУБД |
| Вариант реализации | Oracle / PostgreSQL |
| Детали | Так как имеем дело с legacy системами, скорее всего это Oracle, но при возможности, новые решения лучше строить на PostgreSQL |
| Профиль нагрузки | Чтение (точечное), запись (высокая частота), ACID |
| Требования | ACID, строгая согласованность, транзакционность, низкая latency (<200 мс) |
| Средства защиты | Шифрование (at rest + in transit), RBAC, аудит |

### 2. MDM (мастер-данные)

| Параметр | Описание |
| -- | -- |
| Структура | Реляционная СУБД + поисковый движок |
| Вариант реализации | PostgreSQL + ElasticSearch |
| Детали | Хранение золотых записей клиентов и справочников. Не создает транзакции как OLTP, читается чаще чем пишется |
| Профиль нагрузки | Чтение (высокая частота), запись (низкая частота), дедупликация |
| Требования | Единый идентификатор (одна из бизнес-целей), дедупликация, quality rules |
| Средства защиты | Шифрование, RBAC, аудит, маскирование |

### 3. DWH (регламентированная отчётность)

| Параметр | Описание |
| -- | -- |
| Структура | Реляционная СУБД |
| Вариант реализации | PostgreSQL / Greenplum |
| Детали | Регламентированная отчётность, BI-витрины. Нужны агрегации по всем сущностям. Обеспечение корректной регуляторной отчётности критично для банка |
| Профиль нагрузки | OLAP (тяжёлые чтения, агрегации), batch-загрузка |
| Требования | Историчность, воспроизводимость, SQL-доступ, изоляция от OLTP |
| Средства защиты | Шифрование, RBAC, аудит, маскирование |

### 4. Data Lakehouse (исторические и событийные данные)

| Параметр | Описание |
| -- | -- |
| Структура | Объектное хранилище, распределенные файловые системы |
| Вариант реализации | MinIO + Apache Iceberg + Trino, HDFS |
| Детали | Большие исторические и событийные данные, ML. Для банка критично хранить историю транзакций для аудита и ML (например антифрод) |
| Профиль нагрузки | OLAP (сканы, агрегации), batch-загрузка |
| Требования | Масштабируемость, дешёвое хранение, SQL-доступ, гибкость к данным (schema-on-read) |
| Средства защиты | Шифрование, RBAC, маскирование, токенизация |

### 5. Объектное хранилище (документы и архивы)

| Параметр | Описание |
| -- | -- |
| Структура | Object Storage |
| Вариант реализации | MinIO |
| Детали | Сканы документов, выписки, архивы. Реализуется например на MinIO |
| Профиль нагрузки | Запись (загрузка), чтение (по ссылке) |
| Требования | Дешёвое хранение, версионирование, шифрование |
| Средства защиты | Шифрование, RBAC, аудит, маскирование |

### 6. Графовая БД (связи клиентов и контрагентов)

| Параметр | Описание |
| -- | -- |
| Структура | Графовая СУБД |
| Вариант реализации | Neo4j |
| Детали | Связи клиентов, антифрод. В банковской сфере критически важно применять антифрод защиту, а ценность для этого рождается из связей. Такой тип хранилищ имеет узкую нишу, но для своей задачи он необходим. Главное отделять от операционных данных |
| Профиль нагрузки | Обходы графа, поиск связей |
| Требования | Быстрый traversal, гибкая модель связей |
| Средства защиты | Шифрование, RBAC, аудит, токенизация узлов |

### 7. Поисковый движок (поиск по обращениям и клиентам)

| Параметр | Описание |
| -- | -- |
| Структура | Поисковый движок |
| Вариант реализации | ElasticSearch |
| Детали | Полнотекстовый поиск по обращениям, клиентам. Очень важно для контакт-центра, для них критично быстро находить обращения по ключевым словам |
| Профиль нагрузки | Полнотекстовый поиск |
| Требования | Быстрый поиск, релевантность |
| Средства защиты | Шифрование, RBAC, аудит, маскирование |
