# tech-roadmap.md — технологическая дорожная карта: FinUnion + RetailBank

> Назначение документа: определить технологическую дорожную карту для FinUnion + RetailBank на 12 месяцев. Разделить технологии и подходы по зонам (Adopt, Trial, Assess, Hold) и бъяснить, почему каждая технология попала в свою зону.

## Технологическая дорожная карта (по зонам)

Thoughtworks Technology Radar определяет следующие зоны:

- **Adopt**: проверено, безопасно, можно в продакшене.  
  Соответствует технологиям: уже используются или готовы к использованию, легко внедряются.
- **Trial**: перспективно, но есть риски.  
  Соответствует технологиям: дают большую ценность, но требуют проверки применимости на пилоте на ограниченном домене.
- **Assess**: интересно, но не проверено.  
  Соответствует технологиям: которые требуют глубокого изучения и оценки, но достаточны интересны на будущее.
- **Hold**: рискованно или устарело.  
  Соответствует технологиям: которые лучше не использовать, они устарели или выводятся из эксплуатации.

### Adopt (проверено, можно в продакшене)

| Технология | Роль | Почему Adopt |
| -- | -- | -- |
| **PostgreSQL (DWH)** | Регламентированная отчётность, BI | Open-source, ACID, зрелая СУБД, команда знает SQL |
| **Airflow** | Оркестрация batch-пайплайнов | Стандарт для ETL, зрелый, большое сообщество |
| **Kafka** | Event streaming | Стандарт для async-событий в банках |
| **Debezium** | CDC (захват изменений) | Стандарт для CDC, работает с PostgreSQL/Oracle |
| **API Gateway** | Sync REST для MDM | Проверенное решение (Kong, NGINX) |
| **MDM Customer Hub** | Золотая запись клиента | Объявлено в BIAN, является хорошей стандартной практикой |
| **Read Replica** | Реплика для batch | Стандарт для разгрузки мастера |

### Trial (перспективно, но нужно пилотировать)

| Технология | Роль | Почему Trial |
| -- | -- | -- |
| **Data Lakehouse (S3 + Iceberg + Trino)** | История, события, ML | Перспективно, но новая технология для команды, нужен пилот на одном домене (например, Карты) |
| **DataHub** | Каталог, lineage | DataHub — хороший выбор для каталога данных. Но нужна интеграция с Airflow (DAG scanning), это надо обкатать на пилоте. |
| **dbt** | ELT-трансформации | Стандарт для ELT, но новая технология для команды, нужен пилот на DWH |
| **CDC (Debezium) для истории** | Захват изменений для Lakehouse | Перспективно, но сложно (WAL-логи, Kafka, Iceberg), нужен пилот на Картах |

### Assess (интересно, но не проверено)

| Технология | Роль | Почему Assess |
| -- | -- | -- |
| **Data Mesh (data products)** | Доменные data products | Data Mesh — организационный подход. Нужна очень хорошая зрелость команды и культуры, проработанные операционные процессы |
| **Flink** | Stream processing (real-time антифрод) | Перспективно, но новая технология, нужно оценить сложность |
| **Trino для федеративных запросов** | SQL-доступ к Lakehouse | Мощно, но сложно настроить, нужно оценить |

### Hold (не использовать)

| Технология | Роль | Почему Hold |
| -- | -- | -- |
| **RB CRM** | CRM RetailBank | Выводится (миграция клиентов в MDM) |
| **RB Core** | Core Banking RetailBank | Выводится (миграция счетов в FU Core) |
| **RB Cards** | Card Processing RetailBank | Выводится (миграция карт в FU Cards) |
| **RB Loans** | Loan System RetailBank | Выводится (миграция кредитов в FU Loans) |
| **RB DWH** | DWH RetailBank | Выводится (миграция отчётности в DWH) |
| **RB BI** | BI RetailBank | Выводится (миграция дашбордов в BI) |
| **Point-to-point интеграции** | Интеграции RetailBank | Унифицируются через Integration Layer |
